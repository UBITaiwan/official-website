# Flows —— 標準作業流程

這個目錄放的是**專案特有的操作流程**。

AI agent 對一般的網頁開發很在行，但不會知道這個專案的規矩——
哪些設計是刻意的、新增一筆紀錄要加在哪裡、照片能不能直接用。
這些流程就是把那些「它不可能自己知道的事」寫下來。

> **給 AI agent：**有對應 flow 的工作，一律照 flow 做，不要自己發明步驟。
> flow 裡的規則是這個專案特有的，你的通用做法在這裡通常是錯的。
>
> 收到「我要改 XXX」時的**第一個動作是開分支，不是提問**——
> 理由與步驟見 [修改流程](修改流程.md)。

---

## 一定要先看

| 流程 | 什麼時候用 |
|---|---|
| **[怎麼開始](怎麼開始.md)** | **第一次用這個專案**，或對方問「我要怎麼開始」 |
| **[修改流程](修改流程.md)** | **每一次改動**。不管改什麼都從這裡開始 |
| **[本機預覽與環境檢查](本機預覽與環境檢查.md)** | **第一次在這台電腦工作時**，以及合併前想先看畫面。兩半是同一件事 |
| **[推送前檢查](推送前檢查.md)** | **每次推送之前**。連結、資安、無障礙，一支腳本跑完 |

## 特定情況

| 流程 | 什麼時候用 | 狀態 |
|---|---|---|
| **[新增國際交流](新增國際交流.md)** | 加一場高峰會或國際會議（**新增年度報告也看這份**） | 可用 |
| **[出錯回復](出錯回復.md)** | 改壞了要復原、dev 站怪怪的、不小心動到 `main` | 可用 |
| 正式上線 | 切換到 ubitaiwan.org | 待 Cloudflare 設定後補 |

> **這兩件事刻意沒有獨立的 flow**：換照片、更新計畫時程。
> 它們原本列在這裡待補，2026-09 決定不寫——**走 [修改流程](修改流程.md) 就夠了**，
> 專案特有的規則已經有地方記著：
>
> - 不可憑檔名臆測照片內容、白字壓照片要算對比 —— `AGENTS.md`「文字與圖像的原則」
> - 計畫時程要人工推進（下次 2026/11/01）—— [交接手冊](../交接手冊.md) 第五節
>
> 多一份 flow 就多一份要維護、會過期的文件。
> **不要因為看到這兩件事沒有 flow 就補上。**

## 這些流程也會過期

流程描述的是**現在**的做法。網站會改，做法也會改。

發現流程寫的跟實際情況不符時，**以實際情況為準**，並請 AI 更新流程：

> 你做的和 flows 裡寫的不一樣，請確認哪個是對的，然後把流程改成正確的。

已知會讓流程過時的事：

- **Cloudflare 正式環境上線後**——「修改流程」第 6 步提到的 dev 站網址與部署行為會改變
- **部署方式改變時**——同上
