# 校稿

> 檢查網頁上的文字：錯字、通不通順、有沒有照 [寫作規範](../寫作規範.md)、
> 事實有沒有來源。**只檢查、提建議，不改檔案。**負責人同意了才改。

---

## 什麼時候用

| 情境 | 誰啟動 |
|---|---|
| **要推上去之前**，這次有改到網頁上的文字 | **AI 主動做**。[推上去](推上去.md) 的第 1 步就是校稿，負責人不用記得 |
| 改到一半想先確認 | 負責人說「幫我校稿」「幫我看看文字有沒有問題」 |
| 想整頁檢查一遍 | 負責人說「幫我把 XX 頁整頁校稿」 |

只改了版面、圖片、程式，沒有動到文字，就不用校稿。推上去時跟對方說一聲
「這次沒有改到文字，所以不用校稿」，再往下走。

---

## 給 AI 的話

```
幫我校稿。
```

一般的說法也可以，例如「幫我看看文字」「檢查一下有沒有錯字」。

---

## 它應該做什麼

### 1. 確定範圍

**預設只看這個分支改到的文字**，不是整個網站：

```bash
git fetch origin
git diff origin/main -- src/pages src/data
```

這會同時列出已經 commit 和還沒 commit 的改動。只看讀者看得到的文字
（內文、標題、圖片替代文字、頁面描述），程式碼和樣式不看。

**份量跟著改動大小走。**只改了一個錯字，就只看那一句；
新增了整段或整頁，才需要走完下面每一項。

對方說「整頁校稿」時，範圍才是那一整頁。

### 2. 分出原有內容和新內容

| | 怎麼認 | 檢查到什麼程度 |
|---|---|---|
| **原有內容** | `main` 上本來就有的文字（協會已經認可過的聲音） | 只提**錯字、明顯不通順、不符寫作規範**的地方。**不提語氣、措辭偏好、AI 腔** |
| **新內容** | 這個分支新寫、或整段重寫的文字 | 下一步的每一項都要檢查 |

原有內容被這個分支改過時，也要看**改得是不是太多**：
寫作規範說原有內容以微調為主。改動明顯超過微調的話，要在建議表裡提出來。

### 3. 逐項檢查

| 類別 | 檢查什麼 | 適用 |
|---|---|---|
| **格式** | 中英文、數字之間的空格，全形標點，「」《》的用法，破折號（見寫作規範第二節） | 原有＋新 |
| **用詞** | 「基本收入」、專有名詞統一寫法、三種國際活動有沒有混用、台灣用語（見寫作規範第一節） | 原有＋新 |
| **錯字** | 同音或形近的錯字，例如在／再、的／得／地、做／作、已／以 | 原有＋新 |
| **語意** | 讀不懂、主詞不清楚、句子太長、前後矛盾 | 原有（只提明顯的）＋新 |
| **AI 腔** | 寫作規範第四節的那張表 | 只看新內容 |
| **事實** | 數字、日期、金額、人名、頭銜、引言，有沒有來源；**同一件事在網站其他頁面的寫法是否一致**（例如追蹤人數、實驗金額） | 只看新內容 |

**不要校的東西：**

- `<cite>` 裡的外部作品標題：照原文，見寫作規範第七節
- 引述某個人說的話：照原文逐字保留。懷疑是抄錯時，只提「請對照原始來源」，不要自己改
- 機關、學校的正式名稱：照官方寫法

### 4. 給一張編號建議表

依類別分組，每條建議都要有編號，讓對方能用編號回覆。
**位置用白話講**（「生活自由計畫頁，『誰可以報名』那一段」），不要只給檔名和行號。

格式示意（內容是虛構的，只示範長相）：

```
校稿結果：原有內容 3 條、新內容 4 條建議，另有 2 個事實待確認。

【格式】
1. 生活自由計畫頁，「誰可以報名」第二段
   原文：月收入在1萬元以下
   建議：月收入在 1 萬元以下
   理由：數字前後要加空格

【語意】
2. ……

【事實待確認】（新內容）
| 事實 | 來源 | 狀態 |
|---|---|---|
| 3 位參與者 | 2026 計畫說明會簡報 | ✓ 已對到 |
| 申請人數 215 人 | 找不到 | ⚠ 待確認，請提供來源或刪除 |
```

最後一定要說明怎麼回覆：

> 請告訴我要接受哪幾條，例如「接受 1、3」「格式類全部接受」「全部接受」。
> 不接受的我不會改。事實待確認的部分，請提供來源，或告訴我要刪掉。

**沒有問題就直說「校稿完成，沒有建議」。**不要為了顯得有做事而硬找問題，
更不要把原有內容改寫成你覺得比較好的說法。

### 5. 只改對方接受的

對方回覆之後，**只改接受的那幾條**，改完列出改了哪幾條。

如果是在 [推上去](推上去.md) 的途中校稿，改完接著跑那份流程的下一步（自動檢查）。
在 PR 說明的「校稿」欄填上結果，例如「7 條建議，接受 5 條；1 個事實已補來源」。

## 你要檢查什麼

| | 怎麼看 |
|---|---|
| **它有沒有先問你才改？** | 校稿只會給建議表。你還沒回覆它就改了檔案，請它停下來 |
| **你看得懂建議表嗎？** | 每條都應該講清楚在哪一頁、哪一段、為什麼。只有檔名和行號，請它用白話再講一次 |
| **它有沒有改動原本的語氣？** | 原有內容應該只有錯字、不通順、格式的建議。如果它想把整段改寫，可以拒絕 |
| **新內容的事實都有來源嗎？** | 事實表裡的每一項都要對到來源。「待確認」的不要放著不管，補來源或刪掉 |

## 常見問題

**Q：已經有自動檢查了，為什麼還要校稿？**

自動檢查只抓得到規則明確的事：破折號、少空格、簡體字。
錯字、語意不通、AI 腔、數字寫錯，機器判斷不出來，要靠校稿。

**Q：建議太多，一條一條看很累。**

可以整類接受，例如「格式類全部接受」。格式類的建議通常不會改變意思。
語意和事實類的建議，還是建議一條一條看過。

**Q：我覺得它的建議不對。**

直接說「第 3 條不要」就好，不需要解釋。你比它更懂協會想怎麼說。
如果它的建議跟寫作規範有關，而你覺得規範本身該改，跟維護網站的人提出來。

**Q：校稿可以順便幫我把文章寫得更好嗎？**

那是另一件事，直接說「這段幫我改寫，讓它更 XX」就好。
校稿的原則是只指出問題，不主動改寫。
