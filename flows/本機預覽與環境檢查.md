# 本機預覽與環境檢查

> 一份流程，兩半：**先確認這台電腦跑不跑得動，再把網站跑起來看。**
> 兩半是同一件事——沒有前半，後半做不到。

---

## 什麼時候用

| | 用哪一半 |
|---|---|
| **第一次在這台電腦工作**（新成員、換電腦、重灌） | 環境檢查（第 1、2 步） |
| **改完、還沒合併，想先看看** | 兩半都要，第一次之後可直接跳到第 3 步 |
| **跑任何指令出現「找不到指令」** | 回到環境檢查 |

dev 站要合併之後才會更新，**合併前想看只能在自己的電腦上跑**。

> **環境檢查不只是為了預覽，它是整個專案的前提。**
> AI 在推送之前一定要跑 `npm run build` 和 `npm run check`
> （見 [推送前檢查](推送前檢查.md)），那兩個指令需要的東西跟預覽完全一樣。
> 環境沒裝好，[修改流程](修改流程.md) 走到第 4 步就會卡住，
> 而那時已經改了一堆東西。
> **所以這份檢查要在動工前做，不是改完才做。**

---

## 給 AI 的話

```
請先檢查我的電腦能不能跑這個網站。
缺什麼的話列出來給我看，先問過我再裝。
可以跑的話幫我跑起來，我要看 XX 頁。
```

---

## 它應該做什麼

照順序做。**第 1、2 步是環境檢查，第 3、4 步才是跑起來看。**
環境已經確認過的電腦，可以直接從第 3 步開始。

### 1.（前半）看電腦裝了什麼——Mac 和 Windows 指令一樣

```bash
node -v
git --version
```

這兩個指令在 Mac 和 Windows 上寫法相同。
**有印出版本號就是裝好了**；出現「找不到指令」之類的錯誤訊息就是沒裝
（各系統的訊息文字不一樣，看得懂是「找不到」就對了）。
`npm` 會跟著 Node.js 一起裝，通常不用另外確認。

| 要什麼 | 拿來做什麼 | 沒有會怎樣 |
|---|---|---|
| **Node.js 22 以上** | 把原始碼變成瀏覽器看得到的網頁 | 不能預覽，**也不能做推送前檢查** |
| **npm** | 跟著 Node.js 一起裝 | 同上 |
| **Git** | 開分支、記錄每一次改動 | 整個修改流程走不動 |
| GitHub CLI（`gh`） | 用指令開 PR | 只是比較麻煩，可以改用網頁開 |

**版本太舊也算不合格**，要一併指出來。
Node 的版本需求來自 Astro（`18.20.8 || ^20.3.0 || >=22.0.0`），CI 用的是 22。
**跟對方講「22 以上」就好**，不要把那串版本字串丟過去。

### 2.（前半）缺東西時：列出來，問過才裝

**先分清楚兩種「安裝」**，講給對方聽的時候也要分：

| | 裝到哪裡 | 要不要先問 |
|---|---|---|
| `npm install` | **專案資料夾裡**（`node_modules/`），砍掉重裝就好 | 不用問，直接做 |
| Node.js、Git 本身 | **裝進對方的電腦**，會影響其他專案 | **一定要先問** |

要對方裝東西時，講清楚三件事：**這是什麼、為什麼需要、從哪裡下載。**

| 要裝的 | Mac | Windows |
|---|---|---|
| **Node.js**（選 LTS 版） | nodejs.org 下載 `.pkg` 安裝檔 | nodejs.org 下載 `.msi` 安裝檔 |
| **Git** | 多數 Mac 已內建；沒有的話執行 `git --version` 會跳出安裝提示 | git-scm.com 下載安裝檔 |
| GitHub CLI（非必要） | cli.github.com | cli.github.com |

**規則：**

- **只從官方網站下載**，不要叫對方去別的地方拿安裝檔
- **預設讓對方自己點安裝檔。**這是最不容易出錯的方式，
  而且對方看得到自己在裝什麼
- 對方要求你代勞才用套件管理器（Mac 的 Homebrew、Windows 的 winget），
  **而且要先講清楚那會在電腦裡多裝一套東西**
- **任何需要輸入密碼或系統管理員權限的動作，一律先問過**，不要自己按下去
- 裝完之後**要重開終端機**，新指令才找得到。這一步很常被忘記

### 3.（後半）啟動網站

```bash
npm install     # 第一次才需要，之後可以跳過
npm run dev
```

它會印出一個網址，通常是 `http://localhost:4321`。
**以它實際印出的為準**——如果 4321 被佔用，它會自己換一個。

在瀏覽器打開那個網址就看得到。要關掉的話，在終端機按 `Ctrl` + `C`
（Mac 也是 `Ctrl`，不是 `Cmd`）。

### 4.（後半）不要只叫人自己去看

**視覺上的改動，AI 要先自己截圖給對方看**
（見 `AGENTS.md` 的「改完一定要驗證」）。
本機預覽是給對方自己點來點去用的，不是 AI 免除驗證責任的藉口。

順序是：**AI 先截圖說明改了什麼 → 對方想自己看再跑起來。**

---

## 你要檢查什麼

| | 怎麼看 |
|---|---|
| **它有沒有先問就裝東西？** | 裝進電腦的東西一定要先問過你。`npm install` 不用問 |
| **它有沒有講清楚那是什麼？** | 只說「請安裝 Node.js」不夠，要說那是什麼、為什麼需要 |
| **下載連結是官方的嗎？** | Node.js 認 nodejs.org、Git 認 git-scm.com |
| **它有沒有先給你截圖？** | 只叫你「自己去 localhost 看」是不夠的 |

---

## 常見問題

**Q：我不想在自己的電腦上裝東西。**

可以。那就不要本機預覽，改成請 AI 截圖給你看，
確認沒問題之後合併，再到 dev 站上看完整的結果：

https://ubitaiwan.github.io/official-website/

缺點是**合併之後才看得到**，發現問題要再改一輪。

**Q：網址打開是空白，或連不上。**

先確認跑 `npm run dev` 的那個終端機視窗還開著——關掉網站就停了。
再確認網址跟它印出來的一致，埠號不一定是 4321。

**Q：畫面還是舊的。**

硬重新整理：Mac 按 `Cmd` + `Shift` + `R`，Windows 按 `Ctrl` + `F5`。
還是舊的就跟 AI 說「請清掉快取重開 dev server」。
Astro 的樣式快取有已知問題，記在 `AGENTS.md` 的「已知的陷阱」。

**Q：Windows 上有些指令會出錯。**

`npm run dev`、`npm run build`、`npm run check` 在兩個系統上都一樣，
不會有問題。但文件裡少數指令是 Mac／Linux 寫法
（開頭長得像 `PAGES_BASE=... node ...` 的那種），PowerShell 要改寫。
遇到就跟 AI 說「我是 Windows，請給我對應的寫法」。

**Q：要花多久？**

Node.js 安裝檔約 30MB，下載加安裝通常五分鐘內。
第一次 `npm install` 要下載專案相依套件，視網路速度一到三分鐘。
之後每次 `npm run dev` 都是幾秒鐘的事。
