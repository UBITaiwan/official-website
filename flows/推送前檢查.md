# 推送前檢查

> 在 [修改流程](修改流程.md) 的 commit & push **之前**執行。

---

## 什麼時候用

**每次推送之前。**不管改了什麼都要跑。

---

## 給 AI 的話

```
請先跑 npm run build 再跑 npm run check，把完整輸出貼給我。
如果有問題，請修好之後重跑，直到通過為止。
```

---

## 它應該做什麼

```bash
npm run build     # 先產生 dist/
npm run check     # 檢查 dist/
```

一支腳本檢查三類問題。**不要自己另外寫檢查程式**——
這支腳本存在的理由，就是每次手寫檢查邏輯都會重犯同樣的錯：
忘記處理 URL 編碼的中文路徑、漏掉 inline style 的 `url()`、
只檢查 `href` 而漏掉 `src`。

### 連結

- 站內連結是否指向真實存在的頁面或檔案
- **包含 CSS `url()`**——inline style 與 `<style>` 區塊都算。
  這一項曾經被漏掉，導致一批底圖靜靜上線 404
- 同頁錨點（`#id`）是否有對應元素

### 資安

掃描的是 `dist/`，也就是**實際會被公開的內容**：

- 手機號碼、私人信箱（gmail／yahoo 等）
- API 金鑰、token、密碼
- 雲端憑證（AWS／Google／GitHub／OpenAI）
- 身分證字號
- 本機路徑（`/Users/...`）
- `target="_blank"` 是否有 `rel="noopener"`

### 無障礙

- 每張圖片都有 `alt`
- 每頁恰好一個 `<h1>`（轉址頁除外）
- 標題層級不跳號（h2 之後不會直接出現 h4）
- SVG 若標示 `role="img"` 就必須有 `aria-label`
- 表格有 `<caption>` 與 `scope`
- `<html>` 有 `lang`
- 沒有重複的 `id`
- 連結有可讀的文字

## 你要檢查什麼

看最後一行：

| 輸出 | 意思 | 該怎麼辦 |
|---|---|---|
| `✓ 全部通過` | 沒問題 | 可以推送 |
| `✓ 沒有問題。另有 N 個提醒` | 沒有硬性問題 | **看過提醒**再推送 |
| `✗ 有 N 個問題必須修正` | 不能推 | 請 AI 修好重跑 |

**如果 AI 說「檢查通過」但沒有貼出輸出，請它補上。**
數字（頁數、連結數、圖片數）也要看一眼——如果頁數突然變少，可能有東西壞了。

## 常見問題

**Q：提醒（`!`）可以忽略嗎？**

提醒是「腳本無法自動判斷，需要人看一眼」的東西，不是「不重要」。

最典型的是 PDF 或其他二進位檔——腳本讀不了內容。
目前站上沒有這類檔案，所以不會出現這則提醒；**但如果之後要放 PDF 上去，
務必自己翻過每一頁**。

**這一項有真實案例**：曾經有一份簡報的最後一頁是講者的私人手機與 Gmail，
直接放上公開網站好幾天才被發現。腳本抓不到，只能靠人。

**Q：可以跳過檢查直接推嗎？**

技術上可以，但這三類問題的共同點是**上線後很久才會被發現**：
壞掉的連結沒人回報、外洩的個資沒人通知你、無障礙問題只有受影響的人知道。
跑一次大約十秒。

**Q：想讓提醒也擋下來？**

```bash
npm run check:strict
```

**Q：檢查通過就代表沒問題嗎？**

不代表。腳本只能檢查**能被自動判斷**的事。看不出來的包括：

- 文案寫得對不對
- 版面好不好看（要截圖）
- 文字壓在照片上的對比夠不夠（需要實際取樣像素）
- 照片內容對不對（**一定要打開看過，不可憑檔名判斷**）

這些仍然要人（或 AI 用截圖）判斷。
