# 新增國際交流（加一場高峰會或國際會議）

> 參加完一場國際會議，要把它放上網站時用這一份。
> **新增年度報告是同一套做法**，只是檔案位置不同，見最後一節。

---

## 你要準備什麼

先看這張表就好，**不用先整理格式**，有什麼給什麼。

### 一定要有

| 要什麼 | 說明 | 例子 |
|---|---|---|
| **時間與地點** | 幾年幾月、哪個國家哪個城市 | 2025 年 8 月，巴西里約 |
| **正式名稱** | 這場會議叫什麼 | 2025 巴西 BIEN 高峰會 |
| **一張封面照片** | 會出現在列表上，挑最能代表這場的 | 會場、團隊合照、發表現場 |
| **照片裡是什麼** | 誰、在哪、在做什麼。**這個一定要你講**，AI 看照片猜不準人名 | 「發言的是理事長，右邊第二位是…」 |
| **一段簡介** | 兩三句話說這趟做了什麼 | 「發表台灣青年基本收入政策提案與四篇研究，爭取到 2027 主辦權…」 |
| **兩到四個重點** | 會變成列表上的小標籤 | 青年政策提案／4 篇研究發表／爭取 2027 主辦權 |

### 有的話更好

| 要什麼 | 為什麼 |
|---|---|
| **更多照片** | 內頁可以放，畫面比純文字好看 |
| **照片的原始檔** | 現有照片多半只有 1024 寬，放大螢幕會糊。**有原檔請給原檔** |
| **相關連結** | 新聞報導、發表的簡報或論文、影片 |
| **參與者的話** | 成員的心得或現場的引述，讀起來比流水帳有感覺 |
| **完整的紀錄** | 出團報告、會議筆記、心得文章都可以，愈多愈好寫 |

### 怎麼把檔案給它

**不用整理，直接丟。**

| 你有的 | 怎麼給 |
|---|---|
| Word、Google 文件、PDF | 直接給檔案，或把連結貼給它 |
| **簡報** | 也可以。發表用的簡報通常內容最完整 |
| 照片 | 直接給檔案。一次給一批沒關係 |
| 只有零散的文字 | 貼在對話裡就好 |
| 新聞報導 | 貼網址 |

**不確定夠不夠？直接問它。**先給手邊有的，它會告訴你還缺什麼。

## 給 AI 的話

```
我要新增一場國際交流：（會議名稱、時間、地點）

資料我放在這裡：（附上檔案，或說明在哪）

請先看過資料，告訴我還缺什麼再開始。
```

## 它應該做什麼

### 1. 先看過素材，講清楚還缺什麼

**不要收到東西就開始做。**先讀過，然後告訴對方：
哪些夠了、哪些缺、缺了會變成怎樣。

照片一律**打開看過**再用。`AGENTS.md` 有記錄：
曾經憑檔名把一張結業證書合照當成國際高峰會放上去，整段圖說都是錯的。

**缺封面照片時不要硬湊。**寧可用排版式的封面
（做法見 `impact/international/index.astro` 的 `.ev__cover`），
也不要掛一張來源不明或內容不符的圖。

### 2. 處理照片

放進 `public/images/<這場的資料夾>/`，例如 `public/images/bien-brazil/`。

轉成 webp（這個專案的照片都是 webp）：

```bash
cwebp -q 82 -resize 1600 0 原始檔.jpg -o public/images/<資料夾>/名稱.webp
```

**在那個資料夾放一份 `README.txt`**，寫下照片從哪裡來、什麼時候拍的。
這是既有慣例，`flags/`、`life-freedom/`、`voices/` 等資料夾都有。
半年後沒有人記得一張照片的出處，寫下來才救得回。

### 3. 加進列表頁的陣列

`src/pages/impact/international/index.astro` 最上面的 `events` 陣列，
**加在最前面**（新的在上）。每一筆長這樣：

```js
{
  year: '2025',
  place: '巴西 里約',
  title: '2025 巴西 BIEN 高峰會',
  href: '/impact/international/2025-brazil/',
  image: '/images/bien-brazil/photo-suplicy-online.webp',
  alt: '照片裡是什麼，要打開看過才寫',
  lede: '兩三句話的簡介。',
  tags: ['重點一', '重點二', '重點三'],
}
```

> ⚠️ **不要把新場次掛進 `Header.astro` 的選單。**
> 這是 `AGENTS.md`「不可以做的事」第 2 項：
> 選單只放類別，單筆紀錄一律收進列表頁。
> 改版前就是因為每一場都掛上去，選單長度隨年份線性成長。

### 4. 做內頁

檔名用 `<年份>-<地點>.astro`，放在 `src/pages/impact/international/`，
例如 `2025-brazil.astro`。

現有三篇有兩種寫法，**依素材的性質挑，不要硬套**：

| 素材長什麼樣 | 參考哪一篇 |
|---|---|
| 報告體：會議背景、亮點、連結 | `2024-bath.astro`、`2023-korea.astro` |
| 長篇敘事、照片多、有人的聲音 | `2025-brazil.astro`（文案抽到 `src/data/` 的 json） |

文案很長時，抽到 `src/data/<場次>-content.json`，
比照 `brazil-content.json` 的做法，頁面只負責版面。

### 5. 更新鄰近那一頁的連結——最容易漏的一步

每一篇內頁底部都有「上一場／下一場」的互連。
**新增一場之後，原本最新的那一篇要改成指向新的這一場。**

```bash
grep -rn "impact/international/" src/pages/impact/international/
```

用這道指令把所有互連列出來，確認新的那一場有被連到。

> **這件事真的發生過**：2025 巴西那頁加上去時，
> 2024 巴斯那頁的「下一場」沒有跟著更新，一直指向年度報告。

### 6. 舊網址

**只有舊站原本就有的網址才需要處理。**
全新的場次不需要做轉址頁。

### 7. 檢查

照 [推送前檢查](推送前檢查.md) 跑一遍。特別確認：

- 新頁面有出現在建置結果裡（頁數應該比之前多 1）
- 照片都有替代文字
- 列表頁的封面圖連得到

---

## 你要檢查什麼

| | 怎麼看 |
|---|---|
| **它有沒有先講缺什麼？** | 收到資料就悶頭做，做完才說「這裡沒有素材」是錯的順序 |
| **照片說明對不對？** | 這一項只有你能判斷。人名、地點、場合，AI 看照片猜不準 |
| **列表上排對位置了嗎？** | 新的一場應該在最上面 |
| **上一場那頁有連過來嗎？** | 打開前一場的頁面，拉到最下面看有沒有連到新的這場 |
| **選單有沒有變長？** | **不應該變長。**新場次只進列表頁，不進選單 |

## 新增年度報告也是一樣的

差別只在檔案位置：

| | 國際交流 | 年度報告 |
|---|---|---|
| 列表頁的陣列 | `impact/international/index.astro` | `impact/annual/index.astro` |
| 內頁放哪 | `impact/international/<年>-<地點>.astro` | `impact/annual/<年>.astro` |

其餘（照片處理、不要掛進選單、更新鄰頁連結、檢查）完全相同。
